# HRSN CyberSec

**HRSN CyberSec** یک ابزار ممیزی دفاعی امنیت وب است که برای بررسی اولیه وضعیت امنیتی دامنه‌ها و سرویس‌های اینترنتی، مدیریت پروژه‌های ارزیابی و نگهداری گزارش اسکن‌ها طراحی شده است. رابط کاربری فارسی و راست‌چین است و برنامه علاوه بر اجرا در مرورگر، نسخه دسکتاپ ویندوز مبتنی بر Electron نیز دارد.

> این ابزار برای ارزیابی امنیتی سامانه‌هایی است که مالک آن‌ها هستید یا مجوز صریح بررسی آن‌ها را دارید. نتایج اسکن، جایگزین تست نفوذ حرفه‌ای، بازبینی کد یا ارزیابی جامع امنیتی نیستند.

## قابلیت‌ها

- **اسکن امنیت وب:** بررسی تعدادی از شاخص‌های امنیتی HTTP مانند HSTS، CSP، X-Frame-Options، X-Content-Type-Options، Referrer-Policy و Permissions-Policy.
- **بررسی TLS و گواهی:** ارزیابی نسخه پروتکل TLS، اعتبار زنجیره گواهی و زمان باقی‌مانده تا انقضای گواهی.
- **کنترل مقصد اسکن:** بررسی DNS و محدودسازی آدرس‌های IP خصوصی، loopback، link-local و محدوده‌های رزروشده برای جلوگیری از اسکن مقصدهای داخلی.
- **مدیریت پروژه‌ها:** تعریف پروژه، ثبت دامنه هدف و نگهداری سوابق بررسی.
- **گزارش‌ها و سوابق:** ذخیره نتایج اسکن و مشاهده آن‌ها در ارتباط با پروژه.
- **ابزار Python CLI:** بخش دریافت/استفاده از ابزار خط فرمان پایتون در محیط برنامه.
- **حساب کاربری و همگام‌سازی:** ثبت پروفایل و امکان ارسال اطلاعات ثبت‌نام به سرویس byhrsn.com.
- **رابط کاربری:** پوسته روشن و تاریک و طراحی واکنش‌گرا.

- npm

## نصب و اجرای نسخه توسعه

مخزن را دریافت کنید:

```bash
git clone https://github.com/HRSN919/HRSN-CyberSec.git
cd HRSN-CyberSec
npm install
```

در صورت نیاز، فایل تنظیمات محیطی را از نمونه بسازید:

```bash
cp .env.example .env
```

مقادیر موردنیاز را در فایل `.env` یا در محیط اجرای برنامه تنظیم کنید. کلیدهای API را در مخزن عمومی یا کد سمت کاربر قرار ندهید.

اجرای برنامه در حالت توسعه:

```bash
npm run dev
```

## متغیرهای محیطی

| متغیر | کاربرد |
|---|---|
| `GEMINI_API_KEY` | کلید دسترسی Google Gemini برای قابلیت‌هایی که از API هوش مصنوعی استفاده می‌کنند |
| `APP_URL` | آدرس استقرار برنامه؛ در محیط‌های میزبانی‌شده ممکن است توسط پلتفرم تنظیم شود |
| `BYHRSN_SYNC_URL` | نشانی سرویس همگام‌سازی ثبت‌نام؛ اختیاری و به‌صورت پیش‌فرض روی endpoint پروژه تنظیم شده است |
| `PORT` | پورت اجرای سرویس محلی؛ در صورت تنظیم‌نشدن، مقدار پیش‌فرض سرور 3000 است |
| `HRSN_DATA_DIR` | مسیر ذخیره‌سازی داده‌های محلی؛ در صورت تنظیم‌نشدن، پوشه `data` در مسیر کاری برنامه استفاده می‌شود |

فایل `.env.example` فقط نمونه تنظیمات است. مقادیر واقعی و محرمانه را در آن ثبت نکنید.

## ساخت نسخه ویندوز

برای ساخت فایل نصب ویندوز (NSIS، معماری x64):

```bash
npm run build:desktop
```

خروجی نصب‌کننده در پوشه زیر قرار می‌گیرد:

```
dist-electron/
```

فرمان‌های مجزای ساخت:

```bash
npm run lint
npm run build
npm run build:server
```

همچنین GitHub Actions برای اعتبارسنجی و ساخت نصب‌کننده ویندوز پیکربندی شده است. اجرای workflow از بخش **Actions** مخزن قابل مشاهده است. در صورت انتشار نسخه با tag مطابق الگوی `v*`، workflow انتشار مربوط را نیز اجرا می‌کند.

## ذخیره‌سازی داده‌ها

اطلاعات پروژه‌ها، کاربران و نتایج اسکن در فایل داده محلی برنامه نگهداری می‌شوند. در نسخه دسکتاپ، مسیر داده از پوشه اختصاصی کاربر برنامه در سیستم‌عامل گرفته می‌شود؛ بنابراین حذف و نصب مجدد برنامه لزوماً داده‌های کاربر را حذف نمی‌کند.

از پوشه داده برنامه به‌صورت منظم نسخه پشتیبان تهیه کنید. فایل‌های داده ممکن است شامل اطلاعات شناسایی کاربران و جزئیات اهداف ارزیابی باشند؛ آن‌ها را عمومی یا بدون کنترل دسترسی منتشر نکنید.

## ملاحظات امنیتی و محدودیت‌ها

- فقط دامنه‌ها و سامانه‌هایی را بررسی کنید که مجوز انجام ارزیابی آن‌ها را دارید.
- اسکنر برای جلوگیری از دسترسی به شبکه‌های داخلی، آدرس‌های خصوصی و مقصدهای رزروشده را محدود می‌کند؛ این کنترل، جایگزین کنترل‌های امنیتی شبکه نیست.
- وجود یا نبود یک هدر امنیتی به‌تنهایی نشان‌دهنده امن یا ناامن بودن کل سامانه نیست.
- نتایج بررسی TLS و HTTP به وضعیت مقصد در زمان اسکن وابسته‌اند و ممکن است با تغییر پیکربندی سرور تغییر کنند.
- از ارسال اطلاعات حساس، کلیدهای API، رمز عبور یا داده‌های واقعی مشتریان به سرویس‌های هوش مصنوعی یا سرویس‌های همگام‌سازی خودداری کنید، مگر آنکه سیاست محرمانگی و مجوزهای لازم بررسی شده باشند.
